# KAMI MUSUBI iOS 配色方向 v1.0

生成りの紙に、深藍の骨格と朱の印。

---

## 1. 決定

iOS版の基調を、Dark Forest（近黒緑 `#0A0F0C`）から**和のエディトリアルの明基調**へ切り替える。

紙を地とし、構造を深藍で締め、朱は一点だけ差す印として扱う。

---

## 2. 根拠

「明るい方が今風だから」ではない。製品の中身が明地を要求している。

| # | 事実 |
|---|---|
| 1 | **読ませる製品である。** 相談結果の画面は1,487行、神社詳細は1,180行。由緒・推薦理由・振り返りと長文を読ませる構造で、ダッシュボードではなくエディトリアル。長文の可読性は明地が優位 |
| 2 | **Webの多数派は既に明地。** 44ページのうち深藍の世界観（`--kt-world-ground: #0b111c`）が適用されるのは home と concierge の2つだけで、残りは shadcn の白基調。iOSを明地にする方がブランドは揃う |
| 3 | **暗地では奥行きが作れていない。** `design/shadow.ts` は黒影を opacity 0.25〜0.28 で定義するが、背景 `#0A0F0C` に黒影はほぼ見えない。`theme.ts` 自身が「奥行きは明度差で作る」と宣言して影を諦めている |
| 4 | **これから入る写真は日中の神社。** 明地なら素直に載る。暗地では写真1枚ごとに暗く落とす処理が要り、恒久的に維持することになる |

補足：現行 `theme.ts` には「ホラー/ゴシック、および黒×金のラグジュアリー表現は明確に対象外とする」というコメントが残っている。暗×金がそこへ転びやすいと分かっていた記録である。

## 3. 基本6色

この6色以外を画面に直接書かない。

| 役割 | 名称 | 値 | 用途 |
|---|---|---|---|
| 地 | 鳥の子色 | `#F5EEDC` | 画面の地。朝の光を受けた紙。Splashの下端と同値 |
| 面 | 白 | `#FFFFFF` | カード・モーダル。地との比 1.18 で面として読める |
| 骨格 | 深藍 | `#172A40` | 見出し・アイコン・選択状態・副次ボタン。**静かな強調はすべてここ**（69箇所） |
| 印 | 朱色 | `#B53A2D` | **主アクションの塗りだけ。1画面に1つ。文字には使わない** |
| 文字 | 墨色 | `#242424` | 本文 |
| 線 | 金茶 | `#B39665` | **枠線・区切りのみ。文字に使わない** |
| 罫 | — | `#CFC2A4` | 区切りの線 |

### 2026-11-19 改訂：朱と深藍の役割を分けた

初版は旧 `gold` の参照をそのまま朱に置き換えたため、ホーム画面だけで朱の塗りが4つ出て安売りの広告のような見え方になった。実機で確認して改訂した。

- `accent`（旧 gold の位置、69箇所）＝ **深藍**。静かな強調はすべてこれ
- `vermilion` を別 Token として新設 ＝ **朱**。主アクションの塗りのみ
- 地を `#F5F1E8` → `#F1ECE1` へわずかに沈め、カードを純白に。白と地の比 1.18 で線に頼らず面が読める

### 2026-11-19 追補：地を鳥の子色へ

起動時のSplash（和の朝焼け）の下端が鳥の子色 `#F5EEDC` のため、本編の地を同値に合わせた。グラデが明けきった色からそのままホームの地へ繋がる。地・沈み面・外側・罫の4系統だけを温め、骨格（深藍）と印（茜）は動かしていない。白カードとの差は 1.16、文字色9種はすべて AA 以上。

朱 `#B53A2D` の最暗面コントラストは地を明るくしたことで 4.43 → 4.51 となり境界を跨いだ。「朱は塗り専用」という規則は数値では守れないため、契約テストを「本文の色に朱を使っていないこと」の検査へ変更した。
- 影の Token を明基調向けに引き締めた（opacity 0.25〜0.28 → 0.06〜0.10）。旧値は近黒の地で見えないことを前提にした値で、生成りの上では黒く濁る

### 金茶を文字に使わない理由

コントラスト比は生成り上で **2.49**、白上で **2.81**。WCAG AA の本文基準 4.5 にも、大きい文字の基準 3.0 にも届かない。

当初の案では Secondary Accent とされていたが、**文字色・アイコン色としては不採用**とし、枠線と区切りに限定する。二次的な強調は深藍で受ける。この判断により `premium.accent` も金茶ではなく深藍を割り当てる。

## 4. コントラスト実測

WCAG 2.1 の相対輝度で実測。採用した文字色は4つの面すべてで AA（4.5）を満たす。

| 文字色 | 沈み面 `#EDE7DA` | 地 `#F5F1E8` | 面 `#FBF8F2` | 浮き面 `#FFFFFF` | 判定 |
|---|---|---|---|---|---|
| 墨色 `#242424` | 12.60 | 13.77 | 14.64 | 15.52 | AA |
| 深藍 `#172A40` | 11.82 | 12.92 | 13.74 | 14.57 | AA |
| 二次 `#5B5750` | 5.83 | 6.37 | 6.78 | 7.18 | AA |
| 補助 `#6B665D` | 4.63 | 5.06 | 5.38 | 5.70 | AA |
| 朱色 `#B53A2D` | 4.72 | 5.16 | 5.49 | 5.82 | AA |
| 杉緑 `#3F6B4A` | 4.99 | 5.46 | 5.80 | 6.15 | AA |
| 琥珀 `#8A5A12` | 4.80 | 5.25 | 5.58 | 5.91 | AA |
| 金茶 `#B39665` | 2.28 | 2.49 | 2.65 | 2.81 | **不可** |

その他：

- 白文字 ／ 朱色 = **5.82**、白文字 ／ 深藍 = **14.57**（いずれも塗りボタンの文字として成立）
- 入力欄の枠 `#8E8472` ／ 面 = **3.48**（UI部品の境界に求められる 3.0 を満たす）
- 面の明度は `subtle 0.80 < base 0.88 < surface 0.94 < elevated 1.00` の単調増加

## 5. 朱色の衝突とその扱い（決定：案A）

朱色を主アクションに置くと、慣習的に赤が担うエラー表示と色相が重なる。

**採用：案A（形で分ける）**

| | 形 | 色 |
|---|---|---|
| 主アクション | 塗り | 朱色 `#B53A2D` の面＋白文字 |
| エラー | 文字＋淡い面 | 朱暗 `#8E2018` の文字＋淡い朱の面＋アイコン |

色相は同族のまま、塗りと文字で役割を分ける。朱印と訂正の朱という和の慣習に沿う。

不採用とした案B（主アクションを深藍にし、朱をアクセント限定にする）は、衝突は消えるが鳥居の朱を主役に置く狙いが弱まるため見送った。案Bへ戻す場合は `action.primary` を `#172A40` に、`border.focus` も合わせて差し替える。

## 6. 適用ルール

### やること

- 画面は Semantic Token を参照する。Primitive の直参照は例外とし、理由をコードに残す
- 朱色は**1画面に1つ**。主アクションか、最重要の状態表示のどちらか一方
- 面の明度は `subtle < base < surface < elevated` の順を保つ
- 影を使う。明地では機能するので、浮き面の分離に使ってよい
- 見出しは深藍、本文は墨色

### やらないこと

- 金茶を文字・アイコンに使う（2.49、読めない）
- 朱色の面を広く敷く。印であって地ではない
- 鳥居の記号を画面に繰り返し置く
- グラデーション。紙と墨の世界に合わない
- `apps/web` を触る。本決定は iOS のみ

## 7. 実装の前提（棚卸し結果）

2026-11-19 時点の実測。

| 項目 | 値 |
|---|---|
| `kamimusubiDark` を直接参照するファイル | 31 |
| 実際に使われている Primitive キー | **16種**（定義は30種） |
| 総参照回数 | 514 |
| Semantic Theme を参照するファイル | 1（`components/ui/Button.tsx`） |
| テーマ外に直書きされた色 | 10箇所 |

使用されているキーと参照数：

```text
gold 71 / muted 70 / text 70 / surface 48 / goldSoft 39 / background 35 /
surfaceSoft 33 / borderHeader 27 / borderGold 27 / borderSoft 27 /
mutedSoft 26 / border 20 / mutedDark 14 / outside 4 / borderGoldDark 2 / borderMuted 1
```

**514箇所を書き換える必要はない。** 16キーの値を差し替えれば全画面が切り替わる。
ただし `gold` / `goldSoft` / `borderGold` / `borderGoldDark` は、朱色を指すと名前が実態と食い違うため、
値の差し替えに先立って役割名（`accent` / `accentSoft` / `borderAccent` / `borderAccentDark`）へ改名する。

## 8. 移行手順

1. **キー名の改名**（見た目は変わらない）。`gold` 系4キーを役割名へ
2. **Platform Theme の追加**。明基調の Primitive と Semantic Theme を定義する。26キーの契約は tsc が守る
3. **切り替え**。画面が参照する Primitive を明基調へ向ける
4. **直書き色の回収**。10箇所のうち、暗地前提の色（エラーの `#FCA5A5` など）を Token へ寄せる
5. **OS設定**。`app.config.ts` の `userInterfaceStyle` を `light` へ。`StatusBar` も `style="dark"` へ
6. **影の見直し**。黒影が見えるようになるため、不可視を前提に逃がしていた箇所を直す
7. **文書の更新**。`docs/design/design-token.md` の保留事項2を決定として書き換える
