# 方位条件UI アクセシビリティ実機確認

> Webとモバイルの自動テストで代替できない、OS・ブラウザ・支援技術固有の確認項目を記録する。

## 対象フロー

1. 現在地を使用する
2. 位置情報を拒否し、駅名・住所入力へ切り替える
3. 検索候補を選択する
4. 都道府県を概算地点として選択する
5. 方位情報を使用しない状態で相談する
6. 推薦理由の後に方位参考情報を確認する

## Web

- [ ] 幅320pxで横スクロール、文字切れ、操作要素の重なりがない
- [ ] ブラウザの文字サイズ200%で横スクロールや情報欠落がない
- [ ] Tab／Shift+Tabの順序が、予定日 → 出発地点の指定方法 → 手動入力 → 候補 → 相談文 → 送信になる
- [ ] EnterまたはSpaceで指定方法、検索候補、送信を操作できる
- [ ] すべての操作要素に視認可能なフォーカスリングがある
- [ ] モード選択時にチェック記号と選択状態が表示され、色だけに依存しない
- [ ] VoiceOverで指定方法をradioとして、現在の選択状態を読み上げる
- [ ] 検索中、候補件数、0件、失敗をライブ領域として読み上げる
- [ ] 位置情報拒否後に「駅名・住所から指定する」ボタンへ移動できる
- [ ] 現在の出発地点名と、確定／概算の別を読み上げる
- [ ] 方位カードの「方位の参考情報」を見出しとして移動できる

## iOS／Android

- [ ] iPhone SE相当の幅とAndroid小画面端末で横切れがない
- [ ] OS文字サイズを最大付近にしてもボタン文言が欠落せず、縦方向へ拡張する
- [ ] すべてのPressableが44×44pt以上で操作できる
- [ ] VoiceOver／TalkBackで指定方法をradioとして、checked／disabled状態を読み上げる
- [ ] 選択済み項目にチェック記号が表示され、色だけに依存しない
- [ ] 検索中、候補件数、0件、失敗、現在の出発地点をライブ通知する
- [ ] 位置情報拒否後の手動入力ボタンが読み上げ・操作できる
- [ ] 都道府県選択で「おおよその位置」と読み上げる
- [ ] 方位カード見出しをheaderとして移動できる
