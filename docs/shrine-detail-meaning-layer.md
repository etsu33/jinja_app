# Shrine Detail Meaning Layer

## 1. 目的

神社詳細ページは、神社情報を網羅するページではなく、ユーザーが「なぜ今この神社なのか」を理解するための意味レイヤーとして設計する。

KAMI MUSUBI における神社詳細は、単なる説明ページではない。
ユーザーの状態、神社の意味、参拝後の行動、歴史・土地性、御祭神・由緒を段階的に接続し、場所を通して自分の状態を整理できる体験にする。

## 2. 基本方針

神社詳細では、情報量より意味密度を優先する。

表示する情報は、以下のいずれかに寄与するものに限定する。

- 今の状態理解に役立つ
- 神社を選ぶ意味が伝わる
- 参拝後の行動につながる
- 歴史や土地性が意味の補強になる
- 御祭神・由緒が場所の厚みとして機能する

単なる豆知識、羅列情報、文脈と接続しない歴史情報は主表示に置かない。

## 3. 情報レイヤー順

神社詳細ページは、以下の順に情報を配置する。

1. 今の状態との接続
2. この場所を選ぶ意味
3. 行動として持ち帰ること
4. 歴史・土地性
5. 御祭神・由緒

上に行くほど「ユーザー自身」に近い情報、下に行くほど「場所そのもの」に近い情報として扱う。

## 4. 主役情報と補強情報

### 主役情報

主役情報は、ユーザーの状態と行動に直接関わる情報である。

- 今の状態との接続
- この場所を選ぶ意味
- 行動として持ち帰ること
- 前回との変化
- 継続しているテーマ

主役情報は、Premium の中心価値として扱う。
神社情報を増やすのではなく、ユーザー自身との接続解釈を深める。

### 補強情報

補強情報は、場所の意味に厚みを出す情報である。

- 歴史
- 土地性
- 再建や変化の背景
- 御祭神
- 由緒
- ご利益
- 象徴

補強情報は、単独で主役にしない。
あくまで「なぜこの場所が今の状態とつながるのか」を支える材料として扱う。

## 5. 各レイヤーの役割

### 1. 今の状態との接続

ユーザーの相談内容や状態タグをもとに、今どのような流れにいるのかを短く整理する。

目的は、ユーザーが「これは自分のことだ」と感じられる入口を作ること。

例：

- 今は急いで答えを出すより、静かに方向を整える流れが見えています。
- 今回は、休むことと次の行動を考えることの両方が出ています。

### 2. この場所を選ぶ意味

その神社が、今の状態に対してどのような意味を持つのかを説明する。

目的は、神社を単なる候補ではなく「今向かう理由のある場所」として見せること。

例：

- この神社は、気持ちを整えながら次の一歩を考える場所として合っています。
- 大きく動く前に、自分の軸を戻すための場所として提案しています。

### 3. 行動として持ち帰ること

参拝後にユーザーが現実へ持ち帰れる行動や視点を提示する。

目的は、神社体験を「読んで終わり」にせず、次の行動へつなげること。

例：

- 参拝後は、すぐに結論を出すより、今気になっていることを一度書き出してみる。
- 帰ったあと、次に小さく試せる行動を1つだけ決める。

### 4. 歴史・土地性

歴史や土地性は、場所意味を補強するために表示する。

目的は、神社の背景を単なる知識ではなく、現在のユーザーの状態と接続すること。

表示方針：

- 歴史は「意味の根拠」として扱う
- 年号や人物名の羅列を避ける
- 再建、変化、守り、土地性など、状態接続に関係する要素を優先する
- Wikipedia 的な説明にしない

例：

- この神社は、時代の変化を越えて受け継がれてきた背景があります。今の状態に対しては、「元に戻る」より「形を変えながら続ける」意味を持つ場所として捉えられます。

### 5. 御祭神・由緒

御祭神・由緒は、歴史・土地性と同じ補強レイヤーとして扱う。

ただし、詳細情報になりやすいため、主表示ではなく折りたたみや補足表示を基本とする。

表示方針：

- 興味があるユーザーが深く読める場所に置く
- 主役情報を邪魔しない
- 御祭神や由緒は、状態や行動意味と接続できる場合に優先表示する
- 信仰的・心理的に断定しない

## 6. Free / Premium の線引き

### Free

Free は、神社との出会いと基本的な納得を提供する。

主に表示するもの：

- 神社候補
- 簡易理由
- ご利益
- 象徴
- 基本的な補足情報
- 保存導線

Free では、神社情報と出会いの入口を見せる。
ただし、個人文脈に深く接続した意味づけは出しすぎない。

### Premium

Premium は、ユーザー自身との接続解釈を提供する。

主に表示するもの：

- 今の状態との接続
- この場所を選ぶ意味
- 行動として持ち帰ること
- 前回との変化
- 継続しているテーマ
- 歴史や土地性を状態に接続した意味づけ

Premium は、情報追加ではなく意味の深掘りとして扱う。

## 7. Wikipedia化を避けるガイドライン

以下は避ける。

- 年号、人物名、祭神名だけを羅列する
- 相談内容と関係のない豆知識を表示する
- 歴史説明が長くなりすぎる
- すべての神社情報を同じ重みで出す
- 神社情報を増やすこと自体をPremium価値にする

以下を優先する。

- 今の状態に関係する歴史だけを出す
- 場所の意味を補強する情報だけを選ぶ
- 短く、余白を残して表示する
- 行動につながる解釈にする
- 「断定」ではなく「捉え方」として表現する

## 8. 既存コードとの対応

現状の `ShrineDetailSectionModel` は以下の section を持つ。

- `reason`
- `proposal`
- `meaning`
- `supplement`

現在の対応候補：

| 意味レイヤー | 既存section候補 | 方針 |
|---|---|---|
| 今の状態との接続 | `proposal` / `reason` | ユーザー体験寄りに整理する |
| この場所を選ぶ意味 | `meaning` item: `meaning` | 継続利用 |
| 行動として持ち帰ること | `meaning` item: `action` | 継続利用 |
| 歴史・土地性 | `supplement` 拡張 | 今後追加 |
| 御祭神・由緒 | `supplement` 拡張 / 折りたたみ | 今後追加 |

## 9. 今後の実装方針

まずは設計を固定し、実装は段階的に進める。

1. section の意味レイヤーを docs で固定する
2. 既存の `meaningSection` を「意味」と「行動」の中心に置く
3. `supplementSection` を歴史・土地性・由緒の受け皿として再定義する
4. 歴史 / 再建 / 土地性 / 時代背景タグを検討する
5. 御祭神・由緒は折りたたみ表示を前提にする
6. 今の状態との接続文生成を設計する
