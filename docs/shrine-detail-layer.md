# Shrine Detail Layer 境界

## 目的

神社詳細ページに置く情報レイヤを定義し、検索・コンシェルジュ・Premium 体験との責務混在を防ぐ。

---

## 神社詳細の責務

神社詳細は、神社そのものを理解するためのページである。

主な責務:

- 由緒・説明の確認
- 所在地・基本情報の確認
- ご利益・タグの確認
- 公開御朱印の確認
- お気に入り、経路案内など次アクションへの接続

神社詳細は、神社情報の正確性と参拝前の理解を担う。ユーザーの状態を深く解釈する主担当ではない。

---

## 情報レイヤ

### 1. Public Layer

誰に対しても同じ情報。

- 神社名
- 所在地
- 由緒・説明
- ご利益タグ
- 公開御朱印
- 基本的な参拝導線

このレイヤは Free / Premium に関係なく閲覧できる前提とする。

### 2. Context Layer

コンシェルジュから遷移したときに付与される文脈。

- 今回の相談に対する推薦理由
- 願い・悩みとの対応
- 推薦候補内での位置づけ

このレイヤは、検索結果や直接詳細アクセスでは過度に出さない。意味づけはコンシェルジュ起点に限定する。

### 3. Personal Layer

ユーザー個人の保存・記録に基づく情報。

- お気に入り状態
- 自分の御朱印記録
- 訪問メモ
- 保存した推薦理由
- 過去相談との関係

Personal Layer は Premium 価値と接続しやすいが、基本的なお気に入り状態など最小限の個人情報は Free でも扱う。

---

## Premium を置ける場所

神社詳細で Premium として扱えるのは、神社情報そのものではなく「自分の文脈との接続」である。

Premium にできるもの:

- コンシェルジュ起点の深い補足理由
- 過去の相談・保存神社との相性比較
- 御朱印や訪問記録を踏まえた再訪提案
- 保存した推薦理由の整理・再表示

Premium にしないもの:

- 由緒・住所・基本説明の閲覧
- 公開御朱印の閲覧
- 基本的な経路案内
- Map / Search からの基本遷移

---

## Map / Search との関係

Map / Search は神社詳細へ到達するための補助導線である。

- Search: 候補を浅く広く比較する
- Map: 位置関係を確認する
- Shrine Detail: 神社を正確に理解する
- Concierge: 自分との意味づけを行う

Map / Search の便利さを Premium の主価値にしない。Premium 訴求が必要な場合は、神社詳細上の Personal Layer に接続する。

---

## 表現ルール

- 神社詳細の本文は、公開情報と個人向け理由を混ぜない
- 個人向け理由は、コンシェルジュ由来または保存記録由来であることが分かる配置にする
- 検索結果カードに長い理由付けを持ち込まない
- 詳細ページ単体で過度な占い・診断風の断定をしない
