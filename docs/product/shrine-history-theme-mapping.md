# Shrine History Theme Mapping

## 目的

KAMI MUSUBIにおける神社ごとの `history_theme` 対応表を定義する。

このドキュメントは、DBの `Shrine.history_theme`、`seed_history_theme.py`、PostHog分析、推薦理由生成の接続基準として利用する。

```text
神社
↓
history_theme
↓
推薦理由
↓
行動テーマ
↓
分析
```

## 分類方針

### 1. MVPでは既存7カテゴリに限定する

```markdown
- 勝負
- 縁
- 守り
- 再出発
- 学び
- 復興
- 静寂
```

`巡り` / `浄化` / `導き` は将来拡張候補とし、現時点では既存7カテゴリへ寄せる。

### 2. ご利益だけで決めない

神社ごとの `history_theme` は、ご利益だけではなく、以下を合わせて判断する。

```markdown
- ご利益
- 神社の由緒
- 御祭神
- 歴史的背景
- 場所性
- コンシェルジュで説明したい意味
```

ただし、今回の初期分類では、まず空欄解消と分析安定を優先する。

### 3. テスト神社は分類対象外

以下は本番推薦・分析対象ではないため、`history_theme` 初期分類の対象外とする。

```markdown
- 101 承認テスト神社
- 102 admin承認テスト神社
- 103 重複検証神社
- 104 重複検証神社
- 105 重複検証神社（別宮）
```

これらは seed の対象に含めない。

## seed_history_theme.py 更新方針

`backend/temples/management/commands/seed_history_theme.py` の `HISTORY_THEME_SEED` に、本ドキュメントの分類済み神社を追加する。

### 方針

```markdown
- 本番神社は可能な限り history_theme を持たせる
- テスト神社は seed 対象に含めない
- 保留神社は追加調査後に分類する
- 既存の history_theme を上書きする場合は、分類理由を確認してから行う
```

### 今回の追加対象

```markdown
- 空欄54件のうち、テスト神社5件は対象外
- 長太稲荷神社 / 給田六所神社 は情報不足のため保留
- 残り47件を seed 追加候補とする
```

```markdown
- concierge_result_impression
- shrine_detail_transition
- route_open
- visit_done
- reflection_saved
- premium_preview_click
- save_prompt_view
```

### 期待する効果

```markdown
- historyTheme = None の減少
- historyTheme別 CTR / CVR の安定
- route_open / visit_done / reflection_saved までの比較精度向上
```

### 確認したい指標

```markdown
- historyTheme null率
- historyTheme別 impression数
- historyTheme別 shrine_detail_transition率
- historyTheme別 route_open率
- historyTheme別 premium_preview_click率
```

## history_theme欠損ゼロ方針

### 目標

本番推薦対象の神社は、原則として `history_theme` を持つ。

```text
公開推薦対象 Shrine
↓
history_theme 必須
```

### MVPの扱い

MVPでは、以下を許容する。

```markdown
- テスト神社は対象外
- 情報不足の神社は一時的に保留
- 保留神社は推薦候補からの除外または fallback 扱いを検討する
```

### 将来方針

```markdown
- 新規 Shrine 承認時に history_theme 入力を必須化する
- ShrineSubmission 承認時に管理者が history_theme を確定する
- PostHogで None が増えた場合は DB分類漏れとして扱う
```
