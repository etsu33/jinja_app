

# Concierge Filter Area Design

## 目的

Concierge First の主導線を保ったまま、相談本文に対して必要な条件だけを補助的に追加できる構造を整理する。

本機能は検索フォームではなく、相談体験を補強するための補助条件エリアとして扱う。

---

## 現在地

### 確認済み

- QUIET FILTER は `ConciergeClientFull.tsx` 内で開閉制御されている
- filter UI 本体は `ConciergeSectionsRenderer.tsx` 経由で表示される
- 詳細入力 UI は `ConciergeFilterPanel.tsx` に集約されている
- 誕生日入力は存在する
- ご利益タグ選択は存在する
- 参拝スタイルは `QUICK_PRESETS` として存在する
- 参拝スタイルは専用 state ではなく `extraCondition` に文章として統合される

---

## 基本方針

### 主条件

相談本文を主条件とする。

例:

- 気持ちを切り替えたい
- 仕事やこれからを相談したい
- 静かな場所で整えたい

### 補助条件

補助条件は、相談本文を置き換えない。

補助条件の役割は以下に限定する。

- 誕生日: 相性補助
- ご利益: 願い補助
- 参拝スタイル: 体験補助
- 自由補足: その他の条件補助

---

## 条件追加エリアの最終ワイヤー

```text
QUIET FILTER
必要なときだけ条件を添える

[条件を追加する]

開いた状態:

1. 相性の参考
   - 誕生日（任意）
   - 表示: あなたの傾向
   - 注意: 占術・診断として前面化しない

2. 参拝スタイル
   - 静かに整えたい
   - 人混みが苦手
   - 近場優先
   - 自然を感じたい
   - 気持ちを切り替えたい
   - 有名な神社が安心

3. 願いごと・ご利益
   - 選択式タグ
   - 初期表示は少数
   - 必要に応じて展開

4. 自由補足
   - その他の希望を文章で補足

[キャンセル] [この内容に反映する]
```

---

## 閉じ状態の表示方針

条件が未設定の場合:

```text
QUIET FILTER
必要なときだけ条件を添える
[条件を追加する]
```

条件が設定済みの場合:

```text
追加済みの条件
- 誕生日あり
- 希望: 金運・商売繁盛 他2
- 希望の補足あり
[クリア]
```

## 実装範囲

### 今回触る範囲

- `ConciergeFilterPanel.tsx` のラベル・説明文整理
- `ConciergeSectionsRenderer.tsx` の閉じ状態コピー整理
- `ConciergeClientFull.tsx` の QUIET FILTER 表示コピー整理

### 今回触らない範囲

- backend の recommendation logic
- payload schema の変更
- `visitStyle` 専用 state の新設
- DB カラム追加
- 誕生日ロジックの正本変更
- ご利益タグの分類変更

---

## 実装判断

### 採用

参拝スタイルは `extraCondition` に統合する。

理由:

- 既存 payload で扱える
- backend 変更が不要
- recommendation への反映経路がすでにある
- MVP段階では十分

### 保留

`visitStyle` 専用 state の追加。

理由:

- schema 変更が必要になる
- backend / frontend の責務変更が発生する
- 今の Concierge First 改修範囲を超える

---

## 注意点

- 誕生日は占術・診断として強く見せない
- ご利益タグを主導線にしない
- 参拝スタイルを検索条件のように見せすぎない
- 条件を増やすほど提案精度が上がる、とは言い切らない
- あくまで「相談に少し条件を添える」表現に留める
