

# 相談状態と人生テーマ（history_theme）の対応表

## 目的

KAMI MUSUBIでは、ユーザーの相談内容を直接ご利益へ変換するのではなく、まず現在状態を整理し、その状態を人生テーマ（history_theme）へ翻訳する。

```text
相談状態
↓
history_theme
↓
神社
```

このレイヤーを持つことで、同じご利益でも異なる推薦理由を生成できる。

---

## 基本方針

- 状態を優先する
- ご利益は補助情報として扱う
- history_themeは継続記録の単位として利用する
- 神社推薦はhistory_themeを経由する

## 推薦ロジックとの接続

推薦時は、ご利益よりも相談状態を優先する。

例:

```text
入力:
金運
+
お金が不安

↓

history_theme = 守り
```

```text
入力:
金運
+
独立したい

↓

history_theme = 勝負
```

同じ金運でも人生テーマは変わる。

---

## 継続記録への利用

履歴にはご利益ではなく history_theme を保存する。

例:

```text
2026/06
守り

2026/07
再出発

2026/08
勝負
```

これにより、ユーザー自身の変化を追跡できる。

---

## 分析基盤との接続

PostHogでは historyTheme を軸に以下を分析する。

```markdown
- impression
- shrine_detail_transition
- route_open
- save_prompt
- premium_preview
```

最終的には

```text
相談状態
↓
history_theme
↓
行動
↓
変化
```

を可視化することを目標とする。
