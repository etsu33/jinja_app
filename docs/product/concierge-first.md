

# Concierge First

最終更新: 2026-06-12

## 目的

本ドキュメントは、KAMI MUSUBI の主導線を **神社検索** ではなく、**相談テーマから神社と出会う体験** として固定するための設計書である。

Concierge First では、トップ画面とコンシェルジュ画面を分断せず、ユーザーが最初に行う行動を「探す」ではなく「相談する」に寄せる。

```text
相談テーマ
↓
状態整理
↓
history_theme
↓
神社提案
↓
詳細確認
↓
経路案内 / 保存 / 振り返り
```

---

## 基本方針

### やること

- トップ画面とコンシェルジュ画面を統合する
- 相談テーマをヒーロー領域に置く
- コンシェルジュをアプリの主導線にする
- 神社一覧・地図は補助導線として扱う
- 誕生日・ご利益・参拝スタイルは条件追加として扱う
- 占術要素は裏側の補助シグナルとして扱う
- 吉方位・相性は詳細 / 補足レイヤーに限定する

### やらないこと

- トップ画面を単なる神社検索入口にしない
- 神社一覧を主導線にしない
- 地図を主導線にしない
- 占星術・九星気学・風水をUI前面に出さない
- 生年月日だけでユーザー状態を断定しない
- 吉方位を推薦理由の主役にしない
- ご利益だけで推薦理由を完結させない
- 「この神社が正解」と断定しない

---

## 画面方針

### トップ画面とコンシェルジュ画面の統合

トップ画面は、サービス紹介ページではなく、相談開始画面として扱う。

主導線は以下とする。

```text
トップ
↓
相談テーマ入力
↓
条件追加
↓
コンシェルジュ結果
```

トップ画面内に相談導線を置き、ユーザーが最初に迷わず相談を始められる構造にする。

### ヒーロー領域

ヒーロー領域の主役は相談テーマである。

表示するもの:

- 相談テーマ入力
- 短い導入コピー
- 相談開始CTA
- 条件追加への軽い導線

表示しないもの:

- 神社一覧の大量表示
- 地図の強い主張
- 占術カテゴリの前面表示
- ご利益タグの過剰な一覧

## 入力責務

### 1. 相談テーマ

相談テーマは Concierge First の主入力である。

該当フィールド候補:

- `query`
- `extra_condition` の一部
- `need_tags`

役割:

- ユーザーの今の状態・願い・悩みを受け取る
- `need_tags` 抽出の正本になる
- `history_theme` への変換元になる
- 神社推薦理由の中心になる

例:

```text
最近疲れている
転職で迷っている
お金の不安を整理したい
人間関係を見直したい
気持ちを切り替えたい
```

注意:

相談テーマは、心理診断ではなく状態整理の入口として扱う。

---

### 2. 参拝スタイル

参拝スタイルは条件追加として扱う。

該当フィールド候補:

- `extra_condition`
- `visit_style_tags`
- `sort_tags`
- `hard_filter_tags`
- `soft_signal_tags`

役割:

- 行きやすさや過ごし方の希望を補足する
- 推薦順位や表示順の補助に使う
- 相談テーマそのものとは混ぜない

例:

```text
静かな場所がいい
徒歩で行ける場所がいい
混雑を避けたい
夜に落ち着いて行きたい
```

注意:

参拝スタイルは、相談テーマより優先しない。

---

### 3. 誕生日

誕生日は任意・補助入力として扱う。

該当フィールド候補:

- `birthdate`
- `astro_profile`
- `astro_elements`

役割:

- Compat Mode の主入力になる
- Need Mode では補助シグナルになる
- 相性説明や詳細補足に使う

注意:

誕生日は残す。ただし、ユーザーの性格・運命・状態を断定するためには使わない。

表現例:

```text
生年月日から見た傾向を、補助情報として参考にしています。
```

禁止表現:

```text
あなたはこういう人です
この運命です
生年月日上、これが正解です
```

---

### 4. ご利益タグ

ご利益タグは補助条件として扱う。

該当フィールド候補:

- `goriyaku_tag_ids`
- `selected_goriyaku_tag_ids`
- `matched_user_selected_goriyaku_tag_ids`

役割:

- ユーザーの明示的な願いを受け取る
- `need_tags` や `history_theme` への補助材料にする
- 神社側の `goriyaku_tags` との一致判定に使う

注意:

ご利益タグは入口であり、推薦理由の結論ではない。

悪い例:

```text
金運が上がる神社です。
```

良い例:

```text
金運という願いを、今はお金の不安を整え、次の判断を落ち着いて選び直すテーマとして受け取れます。
```

## 占術要素の扱い

### 基本方針

占星術・九星気学・風水は、UI前面に出さない。

これらはユーザー体験上の主役ではなく、推薦・相性・補足説明のための弱い補助シグナルとして扱う。

### UIで前面に出さない理由

- 占いアプリに見えやすくなる
- 相談テーマよりも占術が主役になりやすい
- ユーザー状態の断定につながりやすい
- KAMI MUSUBI の価値である「状態整理 → 行動」が弱くなる

### 扱ってよい場所

- 詳細ページの補足説明
- 相性ベースの説明
- Premium の補助的な相性カード
- score_v2 の弱い補助シグナル

### 扱わない場所

- トップの主コピー
- ヒーロー領域の主導線
- 相談開始CTA
- 推薦理由の主結論

---

## 吉方位・相性の扱い

吉方位・相性は、詳細 / 補足レイヤーに限定する。

### 役割

- 推薦理由の補足
- 詳細画面での弱い納得材料
- Compat Mode の説明補助

### 禁止

- 吉方位だけで神社を決める
- 相性だけで神社を決める
- 方角を強制する
- 「この方角しかない」と表現する

### 表現例

```text
方位は主理由ではなく、補助要素として参考にしています。
```

---

## 神社一覧・地図の扱い

神社一覧・地図はサブ導線へ格下げする。

### 神社一覧

役割:

- 神社名や地域から探したいユーザーの補助導線
- コンシェルジュ結果後の比較導線
- 直接検索したい場合の逃げ道

主導線にはしない。

### 地図

役割:

- 位置関係の確認
- 周辺探索
- 経路案内への補助

主導線にはしない。

注意:

「近い神社を探す」だけでは KAMI MUSUBI の価値である状態整理が弱くなる。

## docs/concierge-modes.md との責務境界

### concierge-first.md の責務

本ドキュメントは、画面・導線・入力責務を定義する。

扱うもの:

- トップ画面の主導線
- 相談テーマの配置
- 条件追加の扱い
- 神社一覧 / 地図の位置づけ
- 占術要素をUI前面に出さない方針

### concierge-modes.md の責務

`docs/product/concierge-modes.md` は、推薦モードの判定と処理方針を定義する。

扱うもの:

- `need`
- `compat`
- mode resolver
- modeごとの主入力
- modeごとの推薦理由
- history_theme との接続

### 境界

```text
concierge-first.md
= どの画面で、何を主入力として見せるか

concierge-modes.md
= 入力をどう推薦モードに変換するか
```
