

# 神社詳細 Meaning Layer 監査

## 目的

神社詳細画面の Meaning Layer 改修前に、現在の表示構造・既存データ・Free / Premium 境界・場所意味の生成候補を整理する。

この監査では実装変更は行わない。

---

## 場所意味 生成候補

### history_theme

候補:

- 再出発
- 静寂
- 復興
- 勝負
- 縁
- 学び
- 守り

扱い:

- 歴史本文ではなく、歴史文脈タグとして扱う
- 「この場所をどう受け取るか」の補助軸にする
- タグ単体で歴史説明を生成しない

注意:

- `history_theme` は backend model には存在する
- serializer / views への露出は未確認、または現時点で未露出
- 本文情報なしに歴史説明として扱うと Wikipedia 化しやすい

---

### description

扱い:

- 神社の特徴を表す材料として扱う
- そのまま表示するのではなく、要約・意味変換して使う
- 「神社説明」ではなく「今の状態との接続」に変換する

注意:

- description を前面に出しすぎると、一般的な観光説明になりやすい
- Meaning Layer では、説明本文ではなく接続文の材料として使う

---

### sajin

扱い:

- 祭神の象徴として扱う
- 由緒とは分離する
- 「祭神が何を象徴するか」を、状態接続の補助材料にする

注意:

- `sajin` は祭神フィールドであり、由緒フィールドではない
- 「祭神・由緒」とまとめて表示すると、由緒データがあるように見えてしまう
- 由緒本文がない状態では、由緒説明として扱わない

---

### goriyaku

扱い:

- ご利益を、行動テーマとの接続材料として扱う
- 願望成就の説明ではなく、「今どう受け取るか」に寄せる
- ユーザーの状態整理や次の一歩と接続する

注意:

- ご利益をそのまま出すと、祈願メニュー化しやすい
- Premium 側では、願望ではなく行動意味に変換する

---

### element

扱い:

- 五行・雰囲気の補助材料として扱う
- 神社の印象や受け取り方を補強する
- 主判断ではなく補助判断に留める

注意:

- 神秘化しすぎない
- 固定属性として断定しない
- 「今はこう受け取りやすい」程度の表現に留める

---

### place tag

扱い:

- 土地性・場所性の候補として扱う
- 「なぜこの場所なのか」を補強する材料にする
- history_theme / description / sajin / goriyaku と組み合わせて使う

注意:

- place tag 単体で深い意味を生成しない
- 実在情報と生成文の境界を明確にする

---

## Wikipedia 化しやすい箇所

- `sajin` を「祭神・由緒」とまとめて扱う箇所
- `description` をそのまま神社説明として前面に出す箇所
- `goriyaku` をそのまま願望成就の説明として扱う箇所
- `history_theme` を本文なしで歴史説明のように扱う箇所
- `supplement` が「ご利益 / 祭神 / 相性」の列挙だけになる箇所

---

## 方針

神社詳細の Meaning Layer では、歴史・祭神・ご利益・土地性を主役にしすぎない。

優先順は以下とする。

```txt
状態 → 意味 → 行動 → 歴史補強 → 由緒・祭神補足
```

歴史・由緒・祭神は、ユーザーの状態と行動意味を補強する材料として扱う。

---

## この監査でやらないこと

- 実装変更
- serializer 変更
- API payload 変更
- 神社詳細 UI の並び替え
- history_theme の表示追加
- sajin の表示追加
- 由緒フィールドの新規追加
