# ご利益の概念のルール

このドキュメントは、ご利益を「概念」として1か所で決めるためのルールである。
概念の一覧そのものは `backend/temples/domain/goriyaku_concepts_v1.py` が正本であり、
この表はその写しである（食い違いがあればコードが正しい）。

## 背景

これまで「ご利益」は、場所ごとに別々の仕組みで扱われてきた。

- 札（`GoriyakuTag`）の名前：神社の初期データの文字列を区切って自動で作る。
- 札の番号：作った順に自動で振る。環境によって変わる。
- 承認済みの識別子（18件、`goriyaku_taxonomy_v1.py`）と別名（`goriyaku_alias_v1.py`）。
- 相談の種類との対応表（`need_to_goriyaku_tag_ids.py`）：札の番号で書かれている。

札の番号が環境によって変わるため、対応表が本番の札とずれ、意味の合わない結びつき
（休息 → 家内安全 など）が起きた。ご利益を言語に依存しない「概念の識別子」で決め、
ほかの仕組みはすべてそれを参照する形にする。

## 1. 概念とは

- 概念は「参拝する人の願いの単位」である（例：病気が治ってほしい ＝ 病気平癒）。
- 御祭神・場所・神社の役割（例：総本宮）は概念にしない。

## 2. 分け方・まとめ方

| 場合 | 扱い | 例 |
|---|---|---|
| 1つの札に願いが2つ入っている | 分ける（それぞれの概念に結びつける） | 金運・商売繁盛 → 金運 ＋ 商売繁盛 |
| 送り仮名・表記だけが違う | まとめる（片方を別名にする） | 八方除 と 八方除け |
| 言葉は違うが、相談の種類との対応がまったく同じになる | まとめる | 芸能 と 芸能運 |
| 言葉が近くても、相談の種類との対応が変わる | 分ける | 縁結び（人の縁）と 恋愛成就（恋愛） |

迷ったときは「推薦で区別する必要があるか」で決める。

## 3. 識別子

- 英小文字・数字・アンダースコア（スネークケース）。新しく作る識別子は、英単語1〜3語の名詞句にする。
- `variant`・`legacy`・数字の付け足しは使わない（表記ゆれは別名で扱う）。
- 一度決めた識別子は変えない。使い回さない。使わなくなったら廃止の印を付ける。
- 承認済みの18件の識別子はそのまま使う（語数の決まりの外。例：`leg_lower_back_health` は4語）。

## 4. 表示名と別名

- 概念ごとに日本語の表示名を1つ持つ。ほかの言語の表示名は、あとから足せる形にする。
- 表記ゆれ・意味の近い札の名前は、概念の別名として持つ。
- 1つの名前は、1つの概念の表示名か別名のどちらかにしかならない。

## 5. 札との関係

- 札は、初期データの文字列から自動で作られる「生の表記」として扱う。
- 札の名前は、次のどれかになる。
  - 1つの概念の表示名か別名
  - 願いが2つ入った札（組み合わせの札）：分けた先の概念の一覧
  - どれでもない：未分類
- 未分類の札は、推薦の点数にも、一致したご利益にも使わない。

## 6. 相談の種類との対応

- 相談の種類との対応表には、概念の識別子だけを書く。札の番号・札の名前は書かない。

## 7. 追加・変更の手続き

- 概念を足す・まとめる・廃止するとき、表示名を変えるときは、Mother Ship の確認を通す。
- 概念を足すときは、その概念を付ける神社の根拠（授与・祈祷のご利益として出典で確かめられること）を1社以上示す。根拠のある神社が無い概念は作らない。

| 札の名前 | 分けた先の概念 |

| 勝運・必勝祈願 | victory_fortune |

「勝運・必勝祈願」は、勝運と必勝祈願がどちらも勝負運の概念に入るため、分けた先は1つになる。

## まだ決めていないこと

- 相談の種類（15）と概念の対応表の中身（次の作業で決める）。
- 休息・不安など、意味の合う概念が今の一覧に無い相談の種類の扱い。
- 承認済みの別名の表（`goriyaku_alias_v1.py`、今は「八方除け」の1件だけ）に、この一覧の別名を足すかどうか（Mother Ship の確認事項）。
